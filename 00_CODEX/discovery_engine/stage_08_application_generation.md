# Stage 08: Application Generation

## Purpose

Transform canonical knowledge into reusable products.

Application generation uses validated canonical knowledge to create reusable teaching, workshop, simulation, and operator materials. Applications reference canonical knowledge and do not redefine it.

## Examples

- Books
- Courses
- Executive workshops
- Cinaptic simulations
- Assessments
- Operator playbooks
- AI tutors

## Outputs

- Application drafts
- Course materials
- Workshop designs
- Simulation scenarios
- Assessment-secure materials
- Operator playbooks
- Tutor flows

## Required Questions

- What canonical knowledge powers this application?
- What changed upstream?
- Which applications should regenerate?
- What audience constraints apply?
- What must remain assessment-secure or instructor-only?

## Allowed Work

- Generate materials from canonical objects.
- Adapt complexity to audience and format.
- Preserve provenance and canonical references.
- Separate secure or proprietary content.

## Prohibited Work

- Do not redefine canonical knowledge in applications.
- Do not generate from unvalidated hypotheses unless explicitly labeled exploratory.
- Do not invent readings, citations, dates, point values, or policies.
- Do not expose assessment-secure content.

## Exit Criteria

Applications are traceable to canonical knowledge and can regenerate when the ontology changes.
