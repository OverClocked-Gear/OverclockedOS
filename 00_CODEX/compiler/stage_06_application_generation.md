# Stage 06: Application Generation

## Purpose

Create reusable products.

Application generation transforms canonical knowledge into structured products for teaching, workshops, simulations, tools, and operator use. Applications reference canonical knowledge and do not redefine it.

## Application Examples

- Book chapters
- Course modules
- Executive workshops
- Cinaptic scenarios
- Assessments
- Operator playbooks
- AI tutor flows
- Government-as-a-Service tools
- Terroir OS tools

## Allowed Work

- Generate application materials from canonical objects.
- Link applications back to source concepts, frameworks, and evidence.
- Adapt format, workload, and audience depth.
- Separate assessment-secure materials when relevant.
- Identify outputs that should update.

## Prohibited Work

- Do not redefine canonical knowledge inside applications.
- Do not invent readings, citations, dates, point values, or policies.
- Do not expose assessment-secure materials in public locations.
- Do not modify evidence.
- Do not skip canonical references.

## Outputs

- Application drafts
- Course or workshop materials
- Simulation scenarios
- Assessment materials
- Operator playbooks
- Regeneration logs

## Compiler Questions

- What canonical objects powered this application?
- Which applications should regenerate?
- What outputs should update?
- What evidence or concepts are still missing?
- What must remain instructor-only or assessment-secure?

## Exit Criteria

Applications are generated from canonical knowledge with traceable dependencies and clear regeneration needs.
